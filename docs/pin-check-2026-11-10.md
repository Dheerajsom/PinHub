# Pin check and price coverage (2026-11-10)

Branch `feature/code-pin-check`. Two changes: a new `/check` page that reads
firmware, checks the pin references it recognises against the board's record,
and lists the values it could not follow; and the curated price list grown
from 11 to 31 boards. Follow-up fixes are recorded in
`docs/code-audit-2026-11-11.md`.

## Pin check (`/check`)

Paste code, pick a board, and get each pin reference the scanner recognises
with what the record says about it, plus the references it could not match
and the values it could not follow. Everything runs in the browser; the code
is never sent anywhere. The draft (code and language choice, no board id; the
board lives in the URL) is kept in `sessionStorage` so a reload in the same tab
keeps it. Reading and writing it apply the same bound: code longer than
100,000 characters is never stored and never restored.

### What it reads (`src/lib/code-check/scan.ts`)

Dialects are detected from imports and calls, or chosen by hand:

| Dialect | Pin calls recognised |
| --- | --- |
| Arduino | `pinMode`, `digitalWrite/Read`, `analogRead/Write`, `tone`, `pulseIn`, `shiftIn/Out`, `dacWrite`, `touchRead`, `ledcAttach*`, `digitalPinToInterrupt`, ESP32 `Wire.begin(sda, scl)`, `SPI.begin(sck, miso, mosi, ss)`, `SerialN.begin(baud, cfg, rx, tx)`, `setSDA/SCL/TX/RX/…`, `setPins`, `Servo.attach` (declared `Servo` objects only), `Adafruit_NeoPixel`, `DHT`, `OneWire`, `SoftwareSerial`, `LiquidCrystal` declarations |
| MicroPython | `Pin(n, mode)`, `Pin.cpu.A5`, `Pin.board.X`, `ADC`, `DAC`, `PWM`, `TouchPad`, `NeoPixel`, `DHT11/22`, `OneWire`, `Signal`, `I2C/SPI/UART` with keyword pins (and by id alone, resolved to the record's default pins), `SoftI2C/SoftSPI` |
| CircuitPython | `board.X` in `DigitalInOut`, `AnalogIn/Out`, `PWMOut`, `TouchIn`, `NeoPixel`, `busio.I2C(scl, sda)`, `SPI`, `UART`, and `.direction` / `switch_to_*` |
| Raspberry Pi Python | `RPi.GPIO` (BCM, and physical pins under `GPIO.setmode(GPIO.BOARD)`), `gpiozero` devices including `"BOARD11"` / `"GPIO17"` strings and keyword pins, `lgpio` |
| Pico SDK | `gpio_init`, `gpio_set_dir`, `gpio_put/get`, pulls, IRQs, `gpio_set_function`, `adc_gpio_init`, `pwm_gpio_to_*` |
| ESP-IDF | `gpio_*` calls, `GPIO_NUM_n`, `uart_set_pin`, struct fields (`.sda_io_num`, `.gpio_num`, …), `pin_bit_mask` bits |

Comments, docstrings, string contents (raw strings included) and `#if 0`
blocks are masked before calls are read.

Constants are followed up to eight hops:

- **Followed:** `#define` (honouring `#undef` by position), `const` /
  `constexpr` declarations, `enum` values, file-scope globals written once
  (their initialiser), a function-local `const` whose name is declared nowhere
  else and never written, MicroPython `const(…)`, and Python module-level
  names assigned once. Lists and tuples of these are followed item by item.
- **Not followed:** loop variables, function parameters, anything written
  more than once, `#ifdef` alternatives that define a name with different
  values, and definitions that refer back to themselves (directly or through
  others). These, and any other expression (`pins[i]`), are listed for a hand
  check, never guessed.

### What it says (`src/lib/code-check/check.ts`)

Only record-backed findings:

Only record-backed findings, each worded as what "the record lists":

- **Fix:** power or ground pin used as a signal; output-type use of an
  `input-only` pin; a `reserved` pin (quoting its note, so a header pin the
  record reserves for the module's flash, such as the DevKitC's CLK, is still
  a fix); analog read or write with no ADC/DAC function recorded; ADC2
  (`adc-unavailable-with-wifi`) read when the code starts Wi-Fi ("ADC2 read
  with Wi-Fi on"); a MicroPython bus id that names a different controller
  than the pin carries on a fixed-mux chip (`I2C(0, sda=Pin(2))` on a Pico is
  I2C1).
- **Check:** a `module-memory` pin ("Flash or PSRAM pin": the record lists it
  as used for flash or PSRAM on some modules); strapping, boot and USB or
  serial pins ("Shared with USB or serial"), each quoting the board's source
  note; PWM or a hardware bus signal not recorded on the pin; ADC2 without
  Wi-Fi in the code ("ADC2 pin and Wi-Fi"); one pin used for two functions.
- **Note:** JTAG pins and the onboard LED.

A reference that matches nothing is listed under "Not matched to this board's
record" with the reason (for example "PinHub's record has no Arduino number 99
for this board, so this use can't be checked"); it never claims the pin is
absent from the board.

Bare numbers resolve the way the toolchain numbers pins. Outside Arduino code
they are GPIO numbers as the SDK names them, or physical header positions
under `GPIO.setmode(GPIO.BOARD)` (RPi.GPIO only; gpiozero and lgpio keep BCM).
In Arduino code, of the 126 checkable boards:

- 53 records carry Arduino pin numbers: a bare number matches those
  (`analogRead(0)` matches A0), else a `D<n>`/`A<n>` label on a pin with no
  numeric Arduino number (STM32 records that name pins by port).
- 49 ESP32-family and RP2040/RP2350 boards with no Arduino numbers recorded
  assume GPIO numbering, as their Arduino cores usually do, and say so. On 15
  of them (including Arduino Nano ESP32, Nano RP2040 Connect and the ESP32 and
  RP2040-family XIAOs) the labels carry `D<n>` numbers that differ from the
  GPIO numbers, and the report adds a note that a core numbering by those
  labels puts a bare number on a different pin.
- The other 24 (nRF52/nRF53, micro:bit, Raspberry Pi) match a bare number only
  to a `D<n>`/`A<n>` label the record carries; anything else is reported as
  not checkable, never matched to an nRF port index.

Names (`A0`, `D13`, `PA5`, `GP15`, `board.SDA`) match the SDK name, the
Arduino name, the label parts and the aliases. `LED_BUILTIN`, `Pin("LED")` and
`board.LED` resolve to the pin flagged `onboard-led` (a sketch's own
`#define LED_BUILTIN` wins), or report that none is on the header.

### Limits

- Input: the first 100,000 characters. A longer paste is cut, a notice under
  the editor says so, the verdict cannot read as clear, and a copied report
  states that only the first 100,000 characters were checked.
- 400 pin references per scan. When the code has more (a further reference
  or not-followed value past the 400th), the rest is not read, a notice under
  the editor says "Only the first 400 pin references were checked. The rest
  of the code was not.", the verdict cannot read as clear, and a copied report
  carries the same line. Code with exactly 400 references and nothing after
  them reads normally.
- A list constant with more than 64 entries is not followed.
- 100 not-followed values are listed; the rest are counted ("and N more not
  listed") and still count in the verdict and tally.

The page offers the 126 boards whose records carry chip pin names
(`pinFunctions`); it says so when a search finds none.

### Hand-offs

- **Open in planner** writes the pins as planner claims (`use=` keys), named
  by the constant the code used or by the use.
- **Copy report** writes Markdown with every table cell escaped and control
  characters removed, the bare-number note, the unmatched and not-followed
  lists (with the count past the listed 100), the cut notice when the paste
  was cut, and the reference-cap notice when the scan stopped at 400.

## Known limits

- The scanner reads code statically. Pins chosen at run time, passed through
  functions, or built in loops are listed as not followed.
- Library coverage is the common set above; an unrecognised library call is
  silently skipped, not reported.
- Arduino numbering: GPIO numbering is assumed only on ESP32-family and
  RP2040/RP2350 boards whose record names no Arduino numbers. Cores that
  renumber by label (Nano ESP32 in its default "by Arduino pin" mode, XIAO,
  Nano RP2040 Connect) are not modelled; those boards get the
  second-numbering note, and writing `D13` rather than `13` is exact. On
  other boards a bare number matches only a recorded Arduino number or a
  `D<n>`/`A<n>` label, and is otherwise reported as not checkable.
- References past the 400th are not read. The page says so and the verdict
  stays partial, but the pins past the cap are not checked.
- Hints at the end of very long lines can sit past the textarea's horizontal
  scroll range.
- Live-store prices for the 20 new listings appear after the first hourly run
  on `main` once this is merged.
